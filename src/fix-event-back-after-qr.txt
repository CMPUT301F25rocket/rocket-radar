● Based on my analysis of the code, I've identified several likely causes of
   the back stack issue when scanning a QR code and opening the
  EventViewFragment:

  Root Causes:

  1. Fragment Transaction Directly on NavHostFragment 
  (MainActivity.java:317-320) ⚠️ PRIMARY ISSUE

  EventViewFragment eventViewFragment = EventViewFragment.newInstance(event,
   isOrganizer);
  getSupportFragmentManager().beginTransaction()
          .replace(R.id.nav_host_fragment, eventViewFragment)
          .addToBackStack(EventViewFragment.TAG)
          .commit();

  Problem: This code is bypassing the Navigation Component entirely and
  using raw fragment transactions on the nav_host_fragment container. This
  creates two separate back stacks:
  - One managed by the Navigation Controller
  - One managed by the FragmentManager

  When you press back from EventViewFragment, it tries to pop from the
  FragmentManager's back stack, which returns you to wherever you were
  before (the camera app in your case).

  2. Intent Not Being Cleared After Processing (MainActivity.java:270-373)

  In onResume(), the deep link is handled every time the activity resumes.
  However, there's no call to:
  setIntent(new Intent()); // Clear the intent

  This means if you return to MainActivity, the same QR scan intent could be
   processed again.

  3. onNewIntent Sets the Intent but Doesn't Process It 
  (MainActivity.java:259-262)

  @Override
  protected void onNewIntent(@NonNull Intent intent) {
      super.onNewIntent(intent);
      setIntent(intent);
  }

  This sets the new intent but doesn't do anything with it. The actual
  processing happens in onResume(), which could lead to race conditions.

  Recommended Fixes:

  Fix #1 (Most Important): Use Navigation Controller instead of raw fragment
   transactions at MainActivity.java:316-320:

  // Instead of getSupportFragmentManager().beginTransaction()...
  Bundle bundle = new Bundle();
  bundle.putSerializable("event", event);
  bundle.putBoolean("is_organizer", isOrganizer);
  navController.navigate(R.id.eventViewFragment, bundle);

  Fix #2: Clear the intent after processing to prevent re-processing:

  // After line 328, add:
  getIntent().setAction(null);
  getIntent().setData(null);
  // OR
  setIntent(new Intent());

  Fix #3: Consider handling the intent in onNewIntent instead of onResume:

  Move the deep link handling logic from onResume() to onNewIntent() for
  better control over when intents are processed.

  The primary issue is definitely #1 - mixing Navigation Component with raw
  FragmentManager transactions breaks the back stack behavior.
